{{- if or (and .Values.logs.enabled .Values.logs.insert.enabled (not .Values.logs.insert.persistence.enabled)) (and .Values.traces.enabled .Values.traces.insert.enabled (not .Values.traces.insert.persistence.enabled)) }}

WARNING: an insert pod runs without persistence. The insert buffer (insert.buffer_dir,
under /data/lakehouse) holds every acknowledged row until it is written to object
storage; on an emptyDir it is lost when the pod is rescheduled. Enable
logs.insert.persistence / traces.insert.persistence unless you mount a durable
volume at /data/lakehouse through extraVolumes.
{{- end }}

{{- $peerKey := or .Values.peerAuth.existingSecret (dig "peer" "auth_key" "" .Values.lakehouseConfig) }}
{{- if and (not .Values.peerAuth.enabled) (or .Values.logs.enabled .Values.traces.enabled) }}

WARNING: peer authentication is off (peerAuth.enabled=false). Any client that can reach a
pod's port can call its internal endpoints - /internal/manifest/update,
/internal/cache/clear, /internal/stats/sync, /internal/tenant/sync - and read
/internal/cache/* and (insert pods) /internal/buffer/query, which answers each tenant's
not yet flushed rows to a caller that names the tenant. VictoriaLogs and VictoriaTraces
protect their internal endpoints by the network only: keep the pods on a protected
network (networkPolicy, vmauth in front), or turn peer authentication on.
{{- if $peerKey }}
A peer key is set, so the pods already send it on their peer calls; set peerAuth.enabled=true
and roll the pods again so they require it.
{{- else }}
To turn it on: create a Secret, set peerAuth.existingSecret to roll the key out to every pod,
then set peerAuth.enabled=true and roll again (docs/security.md).
Global-read queries miss the unflushed rows until a key is set.
{{- end }}
{{- end }}
