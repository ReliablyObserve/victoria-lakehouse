- **A change is documented by a file in `changelog.d/` instead of an edit of `CHANGELOG.md` (CI and tooling only; no change to the Lakehouse binaries or to runtime behaviour).** A pull request that changes what ships adds `changelog.d/<PR-or-slug>.<kind>.md` holding its one bullet, so two pull requests no longer edit the same lines of `[Unreleased]`, and no bullet can be filed under a release whose tag does not contain it: the release job turns the fragments present at the release commit into the new version section, leaves out the ones the previous release tag already had, and its release-metadata pull request deletes them, so a fragment is released exactly once and one merged after the release commit lands in the next release. The changelog gate requires a fragment where it required an `[Unreleased]` bullet, accepts a hand-written `[Unreleased]` bullet only until the first release whose tag contains `changelog.d/`, and rejects an invalid, duplicate, symlinked or oversized fragment, one that repeats the lead-in of a released section, and an edit or deletion of a fragment the newest release already took; the registry gate and the feature catalog read `added` fragments as `### Added` bullets; `TestChangelogSectionsDescribeTheirTag` looks for a bullet in `CHANGELOG.md` and in `changelog.d/` at the tag. See `changelog.d/README.md`.
