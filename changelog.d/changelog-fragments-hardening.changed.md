- **The changelog fragment flow is tightened, and the transition for hand-written `[Unreleased]` bullets is gone (CI and tooling only; no change to the Lakehouse binaries or to runtime behaviour).** `## [Unreleased]` must now stay empty: the gate refuses text under it, the release stops before anything is published when it finds some, and the assembler no longer merges it or leaves bullets out by comparing with the previous tag (`release_notes.py --after-tag` is removed with it). The gate reports a duplicate fragment whichever of the two files the pull request adds, validates a fragment whose file type changed, keeps `changelog.d/README.md` a regular file that is never deleted, refuses a bullet filed by hand under a released section (except the bullet of a fragment the same pull request deletes), and allows deleting a fragment whose bullet is already in a released section, which is how a fragment left behind by a metadata pull request that could not merge is cleared. A fragment is also refused for a line separator other than LF, an unclosed code fence or HTML pre block; a fragment left behind by a merged metadata pull request stops the next release instead of being skipped for ever; a release section over 100000 bytes stops the release; and the released-fragment list is checked in the build job, before the publish job pushes anything. A pull request counts as a release-metadata sync only when `CHANGELOG.md` has exactly one new section holding the lines of the fragments it deletes and nothing under `[Unreleased]`; lead-ins are compared without case, inner whitespace or the closing dot; an item of any kind under a released section is guarded; the release notes size is checked in the build job and the assembly is dry-run before anything is built. The test that reports a left-behind fragment fires when the section of the fragment's release exists in `CHANGELOG.md` and the file is still there, or when that release has no section while three newer releases do (its metadata pull request was closed). The update note of a change goes inside its bullet. See `changelog.d/README.md`.
