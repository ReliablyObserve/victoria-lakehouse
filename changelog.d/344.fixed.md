- **Compacted logs and traces files carry the body token blooms of a flushed file (#344).** The compactor encoded its output with its own copy of the Parquet writer, which never wrote the `_bloom_body_rg_N` footer entries, so a compacted file could not skip row groups by a word of the log message and a body search got slower as data aged (measured on 142 compacted files: a rare word read 63.6x, a medium word 13.6x the body bytes of the flushed layout, an absent word 245 KB instead of nothing). Flush and compaction now call one shared writer (`internal/parquetwriter`) with explicit options, so the writer options, the Parquet bloom columns, the footer entries, the statistics and the page index cannot drift apart again; a flushed file is byte-identical to before. A compaction whose merge or encode step panics now fails that group (nothing uploaded, sources untouched) instead of crashing the process. A compacted logs object grows by its token blooms (measured: +14.7 % on a 20k-row fixture whose bodies are nearly all distinct tokens, and +4.1 to +4.2 % S3 bytes on the field-metadata cells that read whole compacted logs objects), and, like flushed logs files, carries footer values that are not UTF-8 until #340 lands.
