#   id | kind | base | head | author | verdict | failing rules | report must contain | title
#
# Exactly nine columns (the replay refuses a row with another count); a literal '|' inside a cell
# is written '\|'. For a synthetic row the title is also the commit subject.
#
# Every row is pinned by sha, so the replay is deterministic. `failing rules` is the exact set,
# so a regression that fails a case for the wrong reason is caught too. When a rule changes on
# purpose, change the row in the same pull request and say why in its description.

# Groups:
#   open       pull requests that were open when recorded (a head that was force-pushed away is
#              reported UNAVAILABLE in CI, never silently skipped; replace the row by the squash
#              commit once the pull request is merged)
#   main       squash commits of main: head is the commit, base its parent
#   synthetic  built in a scratch clone by gate_replay.sh, one temporary commit each
#
# The FAIL rows of old product pull requests are strictness locks: those pull requests predate
