# API data-proof metrics

Pure functions that score a captured answer against a reference, as percentages per quality facet
(`scripts/proof/metrics`). The library uses only the Python standard library.

Metrics: M1 status, M2 error text, M3 row-set (Jaccard, recall, precision), M4 field coverage,
M5 per-field value equality, M6 count delta, M7 series (series set, timestamp alignment, point error
p50/p95/max, points within tolerance, totals, NaN agreement), M8 value sets and hits, M9 traces
(trace and span sets, per-span fields, parent links, span count), M10 order (Kendall, ties excluded),
M11 JSON leaves, M12 schema, M13 truth agreement against a calculation over hot VL/VT, M14 latency
ratio over validated answers only.

Verdicts per request: `exact`, `same`, `fixed`, `improved`, `regressed`, `not-reproduced-on-base`,
`vacuous`, `blocked`, `nondeterministic`, `harness-error`. They are decided on the whole facet vector;
the table shows the worst facet. 100% is shown only for an exact answer. Logs and traces are rolled up
separately and never averaged together.

Surfaces are tagged `vl-native`, `vt-native`, `jaeger` (the native core tier) and `loki`, `tempo`
(focused and daily tiers). Tables list native surfaces first; `--core` limits a run to them.

```
python3 -m scripts.proof.metrics scripts/proof/fixtures/cases            # compact table
python3 -m scripts.proof.metrics scripts/proof/fixtures/cases --check    # fixtures vs recorded expectations
python3 -m scripts.proof.metrics <dir> --core --fail-on-regression
```

A case directory holds `meta.json` (surface, kind, options), `ref.json`, `base.json`, `pr.json`
(`{"status", "latency_ms", "body"}`), `truth_base.json` / `truth_pr.json` for Lakehouse-only truth checks,
and optional `resample-N/` directories that only classify flaky answers. Fixtures are generated by
`scripts/proof/fixtures/_gen.py`.

Tests: `pip install -r scripts/proof/requirements.txt && python -m pytest scripts/proof/tests`.
